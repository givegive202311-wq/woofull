# SEO記事 執筆ルール（チェックリスト）

`workflow.md`（AIっぽさを無くすワークフロー）・`strategy.md`（キーワード優先順位）・`media-plan.md`（メディア設計）を、実際に書くときに迷わないよう1枚のチェックリストに落とし込んだもの。**記事を書く前と、書き終えた後の両方でこのリストを確認する。**

## 0. 書き始める前に確認すること

- [ ] `keyword-list.md`（または今後の`keyword-map.md`）に載っているTier1キーワードか。載っていないテーマを思いつきで書かない
- [ ] **誰の・何の悩みを解決する記事か、1文で言えるか**（例：「インターホンの音に吠える犬に困っている飼い主に、叱らずに直す方法を教える記事」）。これが言えない・ぼんやりしている場合は、構成を作る前にテーマを絞り直す
- [ ] 商品と紐づくテーマか、紐づかないテーマか（media-plan.md方針：紐づかなくてよい。無理に商品をねじ込まない）

## 1. 文字数

- 本文（directAnswer・FAQ含まず）：**1300〜2200字**を目安にする
- 水増し（同じ内容の言い換え、当たり前のことを冗長に書く）で文字数を稼がない。書くことが本当に無ければ、見出しを削って短くまとめる方が良い
- 見出し（H2）は4〜7個、1見出し最低150字

## 2. AIっぽい表現をしない

書き終えたら、以下が残っていないか通し読みでチェックする。

**内容面（誇張・空虚）**
- 誇張語：「革新的」「圧倒的」「劇的に」「まさに」「ぜひ」の乱用
- 根拠のない断定：「みんな悩んでいる」「多くの飼い主が」など、出典のない一般化
- 空のマーケ文句で終わる文（「もっと快適な毎日を」で締めるだけ、など）
- 効果の誇大表現：「必ず治ります」「絶対に直ります」→「サポートします」「傾向があります」程度に留める

**文体面（テンプレ感）**
- 同じ文末・同じ接続詞の連続（「〜です。」の連続、「まず」「そして」「また」の多用）
- **記事をまたいだ構成の使い回し**：全記事が同じ見出しパターン（なぜ／特徴／選び方／注意点／FAQ）にならないよう、テーマの性質（トラブル対応・比較・手順・購入ガイド）に合わせて構成そのものを変える
- ダッシュ（——）や体言止めの多用
- 商品ページの定型文（「Woofullは〜を世界中から厳選しています」等）をそのまま流用しない

## 3. 「誰の・何を」を冒頭で明確にする

- `directAnswer`（冒頭の結論）は、検索してきた人が知りたい答えを2〜3文で先に言う。前置きや世間話から始めない
- タイトルと`directAnswer`を読むだけで、「この記事が誰のどんな悩みに向けたものか」が伝わるようにする

## 4. 事実確認（健康・しつけ系の記事で特に重要）

- 商品の話は`product-facts.md`と必ず照合する（ある機能／ない機能／要確認事項）
- **健康・医療に関わる内容**（下痢、皮膚トラブル、涙やけ、出血など）は、一般的に知られている知識の範囲で書き、診断や治療を断定しない。必ず「症状が続く・悪化する場合は動物病院へ」を入れる
- **しつけ・行動に関わる内容**は、一つの方法を絶対視せず、「合わない場合はドッグトレーナーや行動診療科に相談を」という逃げ道を用意する

## 5. 画像・関連リンク

- 画像は最低2枚（商品がある記事：商品写真、商品がない記事：雰囲気の伝わる汎用写真でも可。ただし実在する画像ファイルのみ使う）
- 関連記事（`relatedArticleSlugs`）を最低1本は必ず入れる。関連商品は「あれば」でよい

## 6. 公開前の最終チェック

- [ ] 文字数：1300字以上か
- [ ] AIっぽい表現（上記2）が残っていないか
- [ ] 「誰の・何を」が冒頭でわかるか
- [ ] 事実確認（商品情報・医療情報）が済んでいるか
- [ ] 他の記事とタイトル・キーワードが重複していないか（カニバリ防止）
- [ ] 画像2枚以上・関連記事1本以上あるか

すべてクリアしたら`src/lib/articles.ts`に追加し、`keyword-list.md`（keyword-map.md）のステータスを`published`に更新する。
